# PRO MAX PROMPT — Rebuild the Entire Delivery System (Do NOT Patch)

The current delivery workflow is fundamentally broken and must be rebuilt from the ground up. Do NOT apply temporary fixes, patches, or workarounds. Analyze the entire codebase, identify the root causes, and redesign the delivery workflow using a secure, production-grade architecture.

## Critical Issue

Orders are automatically completing even when no driver has accepted them.

This must NEVER happen.

---

## Rebuild the Delivery State Machine

Implement a strict delivery lifecycle with the following statuses:

1. Pending
2. Waiting for Driver
3. Driver Accepted
4. Driver Arrived at Pickup
5. Picked Up
6. On the Way
7. Delivered
8. Cancelled

No status may be skipped.

Every transition must be triggered only by the correct actor.

---

## Driver Acceptance Logic

When a customer places an order:

• The order must immediately appear in the Available Deliveries list.
• Every eligible driver must see it in real time.
• The order must NEVER disappear automatically.
• The order must NEVER auto-assign.
• The order must NEVER auto-complete.
• The order must NEVER expire by itself.
• The order must remain visible until:
  - A driver accepts it, OR
  - The buyer cancels it before acceptance.

Nothing else should remove the order.

When a driver presses "Accept Delivery":

Immediately:

- Lock the order
- Assign the driver
- Remove the order from every other driver's screen
